# Практическая работа 3

Вариант 9. Создание и применение динамических библиотек при помощи GCC.

Программа заполняет массив M из 11 элементов или матрицу S размером 4x11
псевдослучайными целыми числами от -50 до 50. Пользователь выбирает объект
в меню и вводит X и Y. Программа выводит сумму элементов, для которых
X <= элемент <= Y. Границы входят в диапазон. Если подходящих элементов
нет, сумма равна нулю. При X > Y программа предлагает снова выбрать пункт меню.
Вводимые числа должны помещаться в тип int. При вводе текста вместо числа
программа сообщает об ошибке и завершает работу.

## Файлы

| Файл | Назначение |
| --- | --- |
| array.c | Заполнение, вывод и обработка массива |
| matrix.c | Заполнение, вывод и обработка матрицы |
| work.h | Общая точка входа в библиотеки: run(int x, int y) |
| main.c | Меню и ввод диапазона |
| load.c, load.h | Загрузка библиотеки, поиск run и выгрузка |
| build_linux.sh | Сборка в Linux с SONAME |
| build_windows.cmd | Сборка в Windows с GCC из MinGW-w64 |

## Linux

Из каталога 3pr:

```sh
sh build_linux.sh
./app
```

Библиотеки собираются с -fPIC и -shared. Файлы libarray.so и libmatrix.so
служат символическими ссылками на соответствующие версии. SONAME библиотек:
libarray.so.1 и libmatrix.so.1.

```sh
nm -D --defined-only libarray.so
nm -D --defined-only libmatrix.so
objdump -p libarray.so.1.0 | grep SONAME
objdump -p libmatrix.so.1.0 | grep SONAME
objdump -p app | grep NEEDED
ldd ./app
```

В обеих библиотеках экспортируется run. Остальные функции объявлены static.
Программа использует dlopen, dlsym и dlclose из dlfcn.h. Вызовы dlopen
получают имена с ./, поэтому запускать app нужно из каталога 3pr.
Системный поиск через LD_LIBRARY_PATH для этих имен не требуется.

libarray и libmatrix отсутствуют в NEEDED и в выводе ldd для app:
они загружаются после выбора пункта меню, а не при запуске программы.
Наличие SONAME само по себе не меняет имя, переданное в dlopen, и не проверяет
совместимость функций. Для нашей программы сохраняется сигнатура run(int, int).

Проверить работу при отсутствии одной библиотеки можно переименованием
ссылки libmatrix.so: режим массива должен работать, а выбор матрицы —
выдавать ошибку загрузки. После проверки ссылку нужно вернуть на место.

## Windows

В командной строке cmd, где доступен GCC из MinGW-w64:

```bat
build_windows.cmd
app.exe
```

Каждая DLL собирается заново из исходников под Windows. Файлы .so и .dll
не взаимозаменяемы. Макрос _WIN32 выбирает LoadLibraryA, GetProcAddress
и FreeLibrary из windows.h. В work.h атрибут __declspec(dllexport)
экспортирует функцию run из DLL. SONAME в Windows не используется.
При несовместимом изменении интерфейса имя DLL можно изменить вместе
с именем, которое передается загрузчику.

## Проверка вычислений

Выбрать 1 и ввести -10 10, затем повторить с пунктом 2. По напечатанным
числам сложить те, которые входят в диапазон, и сравнить с результатом.
Числа меняются при новых запусках, поэтому точная сумма заранее не задана.

Для обоих режимов проверить также диапазоны -50 50, 60 70 и 5 5.
В первом случае суммируются все элементы, во втором сумма равна 0,
в третьем учитываются только элементы со значением 5.

При X = Y допустим диапазон из одного значения. При X > Y выводится
сообщение об ошибке до загрузки библиотеки. Пункт 0 завершает программу.
