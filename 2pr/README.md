# Лабораторная работа 2

Вариант 9. Особенности использования отладчика GDB.

## Задания

1. Вводить натуральные числа до нуля и вывести все числа, оканчивающиеся на 7.
2. В строке до точки оставить слова, начинающиеся с A, D, K, P. Ввод и вывод строки выполнить отдельными функциями.
3. В строке до точки удалить сочетания «ас». Функции ввода и вывода поместить в статическую библиотеку.

## Файлы

| Файл | Назначение |

## Сборка

Команды выполняются из папки `2pr`:

```sh
gcc -std=c11 -Wall -Wextra -Wpedantic -g -O0 task1.c -o task1
gcc -std=c11 -Wall -Wextra -Wpedantic -g -O0 task2.c -o task2
gcc -std=c11 -Wall -Wextra -Wpedantic -g -O0 -c string_io.c -o string_io.o
ar rcs libstrio.a string_io.o
gcc -std=c11 -Wall -Wextra -Wpedantic -g -O0 task3.c -L. -lstrio -o task3
```

Параметр `-g` добавляет отладочную информацию. `-O0` отключает оптимизацию, чтобы было удобнее выполнять программу по строкам. Файл `libstrio.a` создается командой `ar` и подключается к третьей программе при сборке. Отладочная информация добавлена и в `string_io.o`.

Проверить состав библиотеки:

```sh
ar t libstrio.a
```

Результат: `string_io.o`.

## Проверка программ

```sh
./task1 < examples/task1.txt
./task2 < examples/task2.txt
./task3 < examples/task3.txt
```

| Программа | Ввод | Результат обработки |
| --- | --- | --- |
| task1 | `7 12 27 70 107 0` | `7`, `27`, `107` |
| task1 | `12 70 100 0` | Подходящих чисел нет |
| task1 | `0` | Подходящих чисел нет |
| task2 | `Apple banana Dog Kite orange Pear.` | `Apple Dog Kite Pear` |
| task2 | `apple dog kite pear.` | Пустая строка |
| task2 | `.` | Пустая строка |
| task3 | `асфальт каска ананас.` | `фальт кка анан` |
| task3 | `асас.` | Пустая строка |
| task3 | `привет мир.` | `привет мир` |

В первой программе ноль завершает ввод и не обрабатывается. Числа вводятся в диапазоне типа `int`. Отрицательные числа и ввод текста приводят к сообщению об ошибке.

Вторая программа проверяет заглавные латинские буквы A, D, K, P с учетом регистра. Слова разделяются пробелами, табуляцией или переводом строки. Между оставшимися словами записывается один пробел.

Вторая и третья программы читают текст до первой точки. Точка не входит в результат. Максимальная длина текста до точки — 255 байт. Если строка длиннее или поток закончился до точки, выводится сообщение об ошибке.

Исходники и входные файлы сохранены в UTF-8. В третьей задаче удаляется русское сочетание «ас» в нижнем регистре. `strlen` определяет его длину в байтах, а `strncmp` сравнивает последовательность байтов. Обработка идет слева направо за один проход: например, `аасс` превращается в `ас`. Остальные символы и пробелы сохраняются.

## Проверка в GDB

Командные файлы запускаются из папки `2pr`:

```sh
gdb -q -batch -x debug/task1.gdb ./task1
gdb -q -batch -x debug/task2.gdb ./task2
gdb -q -batch -x debug/task3.gdb ./task3
```

В первой программе точка останова установлена на строке 29, перед проверкой `last == 7`. Присваивание `last = n % 10` к этому моменту уже выполнено.

| Итерация | n | last |
| --- | --- | --- |
| 1 | 7 | 7 |
| 2 | 12 | 2 |
| 3 | 27 | 7 |
| 4 | 70 | 0 |
| 5 | 107 | 7 |

Во второй и третьей программах точки останова установлены на `inputString` и `printString`. Команда `where` показывает стек при входе в функцию. Затем `finish` выполняет функцию до возврата в `main`, и повторная команда `where` показывает стек после выхода. Для просмотра аргументов используется `info args`, для чтения строки — `x/s str`.

При остановке внутри функции ввода или вывода кадр 0 относится к этой функции, кадр 1 — к `main`. После возврата остается кадр `main`. В третьей задаче GDB показывает функции из файла `string_io.c`, включенного в статическую библиотеку.

Если исходники изменились, нужно заново собрать программы и проверить номера строк в точках останова.
